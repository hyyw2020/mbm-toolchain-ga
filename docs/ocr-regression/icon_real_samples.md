> **来源**：2026-10-25 用户在测试链接页面反馈的手机截图 OCR 输出（文字誊录）。
> **性质**：**真实样本**——这是目前唯一一份带图标的真实 OCR 输出，比合成图值钱。
> 用户判断：「从形态看大概率是真的——图标被读成『田/自/云/●。』，加上状态栏被一起卷入，

## 初步判读（待 baseline 验证）

| 观察 | 判读 |
|---|---|
| 菜单项文字基本全对 | 「小企鹅输入法 / 虚拟键盘 / 候选窗口 / 剪贴板 / 表情和符号 / 插件 / 高级 / 规则与词库 / 用户词库（含智能候选词）/ Recall 屏幕记忆 / 隐私与密码 / 离线手写」→ rec 对真文字可靠 |
| 每行前缀出现单字（心/C/唱/田/自/云/8/●。/0/田） | **图标被 det 检出为文本框，rec 误识为单字** |
| `0N谷100` + `03:39` 在顶部 | **状态栏被卷入**（纯噪声，且把「ON/时间/电量」拼成乱码） |
| `RecalL屏幕记忆` 大小写混杂 | rec 对中英混排的大小写不稳定（次级问题） |

## 归类

- **缺陷类**：图标误检 + 误识（新缺陷类，此前 30 场景零覆盖）
- **与「DB 重叠重复框」的区别**：那个现象是同一行出现两段重复文字；这里是图标被当成文字。
  根因不同，**上一轮 A/B 实验跑不出来很正常**，因为它压根不在合成集里。
