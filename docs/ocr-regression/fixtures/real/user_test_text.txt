## 三、仍然存在的代码问题（按严重度）

**A. 概率图尺寸假设未校验——可能悄悄复发 #27（最严重）**
`detect()` 里 `prob` 按**输出 shape** 分配，但 `mapH/mapW` 用的是 `scaled.height/width`（**输入**尺寸）：
```kotlin
val mapH = scaled.height; val mapW = scaled.width
System.arraycopy(prob, 0, map, 0, min(prob.size, map.size))
```
一旦模型输出 ≠ 输入分辨率（如 1/4 下采样），只拷进左上角 1/4，框全部错位且**完全静默**——这正是 #27 的失效模式。
✅ 修：`mapW/mapH` 直接取 `shape[3]/shape[2]`，并加 `require(prob.size == mapW * mapH)`。

**B. `crop` 泄漏**
`recognizeInternal`：`val text = recognizeCrop(crop) ?: continue` —— `continue` 前没 `crop.recycle()`。`recSession == null` 时每个 crop 都漏。建议 `try/finally`。

**C. 字典与模型一致性无断言**
`charOf` 假设 `classes == keys.size + 2`（0=blank，1..N=字典，N+1=空格），但 `ensureReady` 不校验。字典与 `ch_PP-OCRv6_rec_small.onnx` 版本一旦不匹配，就**静默输出乱码**（#36 同类）。
✅ 修：`ensureReady` 里断言 rec 输出 `classes == keys.size + 2`，启动即失败而非静默。

**D. cls 模型版本混用（低危，已注释说明）**
det/rec 是 v6，cls 仍是 `ch_ppocr_mobile_v2.0_cls_infer`。你注释说 RapidOCR v3.10 也如此，且 192×48 + 0.5/0.5 与 v2.0 一致 —— 可接受，但建议把归一化常量与 cls 模型版本绑死注释，避免将来换 cls 时忘记改。

**E. `DET_MAX_CANDIDATES` 的 break 只跳出内层 x 循环**，外层 y 继续空转扫全图（功能上不超 1000，但白耗）。

**F. `boxScoreFast` 用 AABB + 逐像素 `pointInPolygon`**，1000 候选 × 旋转框 AABB 在手机上是热点，可能拖慢整机。

**G.（推断，需实测）** 你为游戏小字把 `DET_THRESH` 降到 0.15、`UNCLIP` 提到 1.6，召回上去的同时**误检框必然大增** → rec 推理次数和耗电同步上升。建议用固定样本集量化"召回/误检/耗时"三角。
